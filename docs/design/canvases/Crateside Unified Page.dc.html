3Stem selection · additional sources · getting tracks in (#22)

Read against the repo. Tracks.razor.css, TrackRow.cs, StemRecut.cs, WorkOrder.cs, ADRs 0004/0005/0014/0015 and the issue. Every correction in #22 is carried: no hold, no Done filter, song-keyed rows with per-upload labels, parked has a reason, edits row is side-by-side, panel capped at --table-tracks.

The one idea. There is no separate picker. The stem list is the picker. Every file the track could have is a line; a line is either on disk or not; a checkbox says whether it is wanted. Toggling recolours the same lines into turn 2's diff — teal new, red struck removed, plain kept — so the confirm state is not a second screen and "keep" is the visible default rather than an accident. The same list draws before separation (nothing on disk yet) and after (some on disk). The has vocals / no vocals select is gone; the instrumental release is "Vocal off, Source on" and nothing else.

Names. The list shows the separator's names — Vocal - Full, Instrumental - Clean — because a picker is about files and those are the filenames Ableton shows. crateside's vocal_full ids appear nowhere; the plan panel loses its mono argument list.

Verbs. Swap source stays in the edits row at the top — it replaces the upload the stems are cut from. Add an upload lives inside the list under its own band — it joins the track and deletes nothing. They never share a control.

3eNotes — what the drawing decided, and what it cannot
1 · The plan is now the record. ADR 0004 is reversed here, on purpose.
Once a user can tick six presets and a source, no single fact derives the set — "no vocals" was one of many reasons to leave Vocal - Full unticked. The picker records the plan per track, in crateside's instruction store, and nothing derives it. Cost: has_vocals stops flowing to keytag's ledger; ADR 0005 §6 and §7 built that path and it goes dark. Options: drop the field (and amend keytag's glossary), or infer has_vocals: false when no vocal preset is ticked and the source is kept — an inference, so it should be labelled one in the ledger rather than passed off as a statement.
2 · The warp guide is not a choice.
Drawn pinned: a dot, not a box, "always made". No workflow exists that does not want one, and a tick-box that cannot be unticked is worse than none. If drums becomes a preset in StemForge, the line stays pinned and simply stops being a flag underneath. Re-cuts that keep any file keep the guide too — a new one is cut only when nothing on disk survives.
3 · Local-file identity is unsolved and the drawing does not paper over it.
Every reader joins on StemForge's COMMENT provenance. A local file can be judged and separated (both take a path) but the stems it produces have no video ID, so handoff, the board, the audit and tagging all skip them. Two ways out, neither decided: crateside writes provenance into audio (a second kind of write, against ADR 0003) or keytag mints an identity for a file. Until then the row parks as no identity. Do not ship the Local file tab before this is decided; ship the URL tab alone.
4 · What an added upload does to "done".
Recommendation: adding a source reopens the row — it returns to ready to warp with one outstanding file, because the user has just asked for a new sample and it needs warping like any other. The alternative — leave the row done and let the new file sit untracked — hides work. Rows move on reaching ready to warp, so this is a permitted move.
5 · An additive re-cut needs machinery that does not exist yet.
StemRecut.Apply deletes every staged file and cancels three stages. "Cut 2 more" needs a recipe that runs only the new presets and a handoff that tolerates existing names for the same song — today a name collision fails the whole track (ADR 0005, handoff). The drawing promises "files already in Sample Staging are untouched"; build that or change the sentence.
6 · A preset crateside has never used gets no warning.
Clean and Balanced are StemForge's own presets; the risk is quality, and the user is choosing them precisely because they heard the default fail. The cost line (passes, minutes) is the only thing worth saying.
7 · Order survives.
A re-cut moves the chip from ready to warp to separating · re-cut. By the built rule that is a stage change, not a state the list sorts on, so the row stays put; it moves back into the ready-to-warp group only when it lands there again. An added upload never touches the chip.
8 · Where the pasted-URL record lives.
Not a drawing problem, but the flag "added by URL" assumes crateside can tell. The store that lets a non-playlist track reach Outstanding also has to carry that provenance, or the flag cannot be drawn.

Why no new chip. A re-cut is separation → staging → tagging again; the chip vocabulary already covers each step, and the suffix says why it is happening. The row appears in In flight for the duration, then returns to ready to warp. A rename takes seconds and does not change pipeline state, so it is a flag beside the name — the same slot audit flags use — with the teal dot because work is happening this second. If it half-fails (a file open in Ableton), the flag turns red and the row joins Needs attention with a Retry.
2dOpen questions the drawing cannot settle
1 · Is a re-cut a new fact or a correction?
The drawing shows "was no vocals" and keeps no history. If it is a correction, the old fact should vanish from the ledger; if a new fact, the detail sentence should be able to say "re-cut 2 days ago".
2 · Does a rename survive re-judging?
Drawn as: yes, the override wins over all three sources, always. If a later verdict records a better artist/title, the strip could offer it — "judging suggests X · Use it" — rather than silently replacing.
3 · Preset picker shape.
Drawn as a select-shaped control with two values. When presets arrive: same slot, a menu of named presets with the recipe listed beneath each. Confirm what the preset names are so the "Release" label still reads truthfully.
4 · Re-cut of a track that was never instrumental.
Same control, opposite direction (vocal split → drums-only). Allowed? If so the removed-file count is 3 and the diff is drawn the same way.
5 · Rename while separating.
Brief says it must reach the source tags. Does the running separator pick that up mid-job, or do the stems come out with the old name and get renamed at staging? The button copy "1 file now, 3 at staging" assumes the latter.
6 · Renamed flag: forever, or until Mashup Samples?
Drawn as permanent, neutral, low-contrast. If the user only cares while files are in staging, drop it on done.
7 · Ableton has the file open.
Both operations delete or rename files the user may be warping this second. Drawn as a red flag + Retry after the fact; a pre-check is better if the app can know.

1crateside — one page, one row per track

What I read. The scoping doc only — the repo folders didn't reach me, so vocabulary follows the doc (track, stem, sample, warp guide, Sample Staging, Mashup Samples) and row fields follow its StagingSong table. Flag anything that breaks CONTEXT.md.

System. Dark, warm-neutral. IBM Plex Sans for text, Plex Mono for every number and key so BPM/key line up in a column and read at arm's length. Two accents, same chroma: teal = the machine is doing something; amber = your turn. Red only for needs attention. Nothing else is coloured, so colour alone answers "is anything waiting on me?"

Shape. Frozen header (Separation · Judging · Quota) with nav pinned to its left. One list; filters are pills with counts. State is a column. A row never moves. Expanding shows stems; the Drums warp guide is ghosted and dashed because it is not a kept sample. 1a is the whole page; 1b–1d are the other filters and the held case; 1e–1i are alternatives for the parts you asked to see varied.
