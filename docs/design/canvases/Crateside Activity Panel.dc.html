Activity gets its own section, one line per action

The panel leaves the Over time row and becomes the dashboard's third section, Activity, right under Working now, because it answers the same question a minute later: what is going on, and what just happened. It takes the full content width as a table with fixed columns: when, stage, track, result, how long. Each action is one row: it appears when the stage starts, with a pulsing teal dot, and the same row takes the track page's result line when it finishes. The track name holds one column, so its left edge never moves, and a run of rows for one track shows the name once. Rows are bucketed into Last 10 minutes and earlier, and a finished action keeps a green check while it is in that bucket. Filter by stage, page through everything. Everything in 1a works: the filters, the page size, the pager, and clicking a result to open it.

Where it sits. Third of five sections, under Working now: the two read as one glance (what is running, then what it just did). Over time keeps its two charts and gets the row to itself. The index gains Activity, with the running count in teal while anything runs. Width is the content column up to a new cap, --table-activity: 97.5rem (1560px); the result column takes whatever the fixed columns leave.

One row per action. Joined on the job id. Ordered by when it started, so a running row is replaced in place and never jumps. Started is a clock time to the minute (the machine's locale); hovering it shows 4 min ago. The relative sense comes from the buckets: Last 10 minutes, Earlier today, Yesterday, then dates. A row for the same track as the row above shows a thin rule in the track column instead of the name, also across a mix of tracks; a bucket line starts the name again.

More, and by type. 12 per page by default; 25, 50, 100. Paging is newest first. Page 1 is live; on a later page rows hold still and a line offers the way back when new ones arrive (1c). Stage filters combine; Failed or canceled narrows any of them. Filter and page size are remembered in the dashboard's cookie; the page is not. Counts on the pills are for everything on record.

Running is a teal dot that pulses (the one other animation on the page, after the stage flow's; none under reduced motion), a teal 5% wash on the row, and the time so far in teal in Took, ticking. The result column says what the stage is doing where the app knows: files written of those expected for a separation, the turn for a judging session; otherwise running.

Finished replaces all of that with the result line and the time it took. The check is green while the row is in Last 10 minutes, then drops to a quiet grey: green is done, and only the recent ones are worth a glance. No other highlight.

Failed is a red ✕ and the error in red, prefixed failed:, for good. Canceled is a grey dash and the reason in grey. The Failed or canceled filter finds both.

Long lines end in an ellipsis inside the result column; Took is its own column, so the duration never truncates. The full line is the tooltip, and a click opens it under the row with start and finish times, the job id, and links to Track details and its activity log. The track name truncates the same way at 300px; the link's title holds it whole.

Wording is the job's summary exactly as Track details prints it, without its · 15 s tail (that is Took). Stage names read as activities: Download, Detection, Judging, Separation, Handoff, Tagging.
