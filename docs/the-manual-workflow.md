# The manual workflow

**Status:** reference. This is the workflow **as the user performs it by hand**, recorded so
that anyone changing crateside knows what is being automated and what is being replaced. It is
deliberately *not* the optimised or automated flow, and it will drift from what crateside does.
Where the two differ, this file describes the human one.

Written from the user's own account, 2026-08-15.

## Finding a track

1. **Find something worth having** — usually while browsing YouTube or YouTube Music.
2. **Land on the canonical version.** Several uploads of a song exist; one of them is the right
   master. Picking it is a judgement, and getting it wrong is expensive later, because the
   verdict, the BPM and the stems are all downstream of it.
3. **Add the URL to the `StemForge Queue` playlist**, to work through in a batch later.

Time passes. A batch begins.

## Before Ableton, in either order

- **Get the key and the BPM.** The key has to be right; the BPM is a warp starting point and is
  rarely exactly right anyway. Historically this was a web search and a look at Tunebat; then
  keytag's `detect-key` skill; now crateside's verdict run ([judge.md](judge.md)).
- **Separate.** Vocal, instrumental and drums. For an already-instrumental release, drums only —
  the source track is kept and *is* the instrumental. StemForge takes either the YouTube URL or
  a local file, so a file already downloaded for key detection is reused; if separation runs
  first, StemForge fetches the source itself, and `--keep-source` is the flag that avoids
  downloading the same track twice.

## In Ableton

1. **Move the stems into `Sample Staging`.** Moving files into that folder is what makes them
   appear in Ableton's user library. The folder exists because one flat library made warped and
   unwarped material impossible to tell apart; staging holds what is ready to import but not yet
   warped and tagged.
2. **Tag the samples** with key and type keywords.
3. **Load the vocal, instrumental and drums into arrangement view**, set the project tempo to the
   detected BPM, select all three clips, and toggle warp.
4. **Warp against the drums.** With all three clips selected and the drum clip selected *last*,
   the clip view shows the drum waveform and its transient markers while warp markers apply to
   every selected clip at once. That is what makes accurate warping possible on a track recorded
   without a click: kick and snare hits are visually unmistakable, so a marker can be dropped on,
   say, the beat-2 snare of every bar, and the vocal and instrumental come along perfectly in
   sync. Even at a fixed whole-number tempo it earns its place — it shows exactly where the beat
   enters, so a single marker can be lined up against the start of a transient.
5. **Delete the drum stem.** It has done its job. This is a step, not tidying up.
6. **Trim to the first verse and Save Default Clip.** Trim the start of the vocal and instrumental
   to the bar where the first verse begins, then save that as the default clip, so dragging the
   sample in from the library later always starts there. Nothing is destroyed — the audio before
   that point is still in the file; only the default drag-in position moves. This is what makes
   an arbitrary vocal and an arbitrary instrumental line up on the first try.
7. **Check the tags** one last time.
8. **Drag the samples into `Mashup Samples`.** Done.

Often the next thing is to try the new vocal or instrumental against other samples in compatible
keys, since they are already loaded. When working through a batch quickly, the clips are deleted
and the next track begins.

## The import signal

The four closing steps — delete the drum stem, save the default clip, check the tags, move to
`Mashup Samples` — can be done in any order, but **the move is kept last on purpose**. The user's
own indicator that a song is finished is that it is in `Mashup Samples`. A sample sitting there
unwarped, untagged or mistagged would be a mistake, not a state the workflow produces.

This matters to crateside because [ADR 0002](adr/0002-there-is-no-warped-signal.md) is right that
nothing on disk says "warped" — and it does not need to. **Presence in `Mashup Samples` is a
composite signal for the whole closing sequence**, generated by the user's habit rather than by
Ableton, and it is stronger than a warp flag would be because it also covers tagging and the
default clip.

It holds up against the library as it actually is (measured 2026-08-15, 435 `.flac` files in
`Mashup Samples`):

| observation | count | what it says |
|---|---|---|
| drums stems | **0** | the warp guide never survives the move — the discipline is total, not typical |
| instrumental | 211 | |
| vocal | 209 | near-perfect pairing; the ragged cases are the ones below |
| no preset suffix | 15 | retained sources: instrumental releases (Snail's House, PSYQUI, Camellia…), plus one official instrumental and one official acapella |

Zero drums across 435 files is the load-bearing number. It is what makes "in `Mashup Samples`"
readable as *finished* rather than merely *moved*.

**What this does not license.** The *absence* of a drum stem from `Sample Staging` is a much
weaker claim and is not the same signal — a track can have been separated and never touched.
Only the move is deliberate.

## Two shapes the model has to admit

- **Instrumental releases** — no vocals to separate out, so drums are the only stem and the
  source track is the sample. Recorded as `has_vocals: false`. Fifteen of these are already in
  the library.
- **Official instrumentals and acapellas** — a release that *is* a stem without anyone having
  separated it (`SUPADOPA (Official Instrumental)`, `Gucci Gucci (Acapella)`). Same shape on disk
  as a retained source: real audio, no StemForge preset. Not yet modelled as distinct from an
  instrumental release, and there are two of them, so it has not earned a distinction yet.
