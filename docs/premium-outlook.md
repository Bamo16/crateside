# Spotting a non-premium queue item from the YouTube API

**Question.** Can crateside warn, from API metadata alone, that a queued URL will not yield a
YouTube Premium download — without shelling out to yt-dlp with cookies?

**Answer: yes, for the positive case, exactly.** Measured, not assumed.

## The signal

`snippet.description` contains **`Auto-generated by YouTube`**. YouTube writes it on every
auto-generated Music art track, alongside a leading `Provided to YouTube by <distributor>`.

`playlistItems.list` already returns the description on the call the Queue view makes anyway,
so **the signal costs no extra quota** — no second request, no yt-dlp.

## What it was measured against

The 552-video corpus in `V:\Repos\Yt-dlp_Formats`, resolved three ways (logged out, signed-in
free, signed-in Premium). All 552 were still live and were re-queried through
`videos.list` (12 quota units).

| signal | fires | false positives | precision | recall |
|---|---:|---:|---:|---:|
| **`Auto-generated by YouTube`** | 326 | **0** | **100%** | 77.6% |
| `Provided to YouTube by` | 326 | 0 | 100% | 77.6% |
| channel title ends `- Topic` | 327 | 1 | 99.7% | 77.6% |
| `contentDetails.licensedContent` | 415 | 34 | 91.8% | 90.7% |
| `categoryId == 10` (Music) | 496 | 88 | 82.3% | 97.1% |
| `topicDetails` mentions music | 517 | 103 | 80.1% | 98.6% |

Two results carry the design:

1. **The marker set is *identical* to yt-dlp's.** The 326 videos it fires on are exactly the
   326 that yt-dlp reports an `artist` for — StemForge's `IsMusicTrackEntity` test. Not
   "correlated with": the symmetric difference is **0**. The API reproduces a signal that was
   assumed to require yt-dlp.
2. **Those 326 were premium 326/326.** No false positives.

## What it cannot do

Of the 226 videos without the marker, **94 (42%) were still premium**. Nothing available in
the API separates them: within that subset, `licensedContent` reaches 62% precision and
`licensedContent + categoryId 10` only 69%.

So the absence of the marker predicts *nothing*, and the UI says so. The flag reads as
"a better URL for this song may exist — worth checking", never as "this will download badly".
Claiming the latter would be wrong two times in five.

## Rejected alternatives

- **`- Topic` channel title.** One false positive, and misleading to verify by eye: YouTube's
  UI attributes art tracks to the *official artist channel* while the API still reports the
  Topic channel. The screenshot that prompted this work showed `corneliusofficial`, but
  `videos.list` for the same video (`Wsk3rBhYqoc`) returns `Cornelius - Topic`. The
  description marker sidesteps the discrepancy.
- **`categoryId`, `topicDetails`, `licensedContent`.** All high-recall, low-precision. A
  warning that fires on 88–103 healthy tracks would be ignored within a week.
- **Shelling out to yt-dlp.** Unnecessary given the above, and it would need cookies, a
  subprocess, and seconds per item.

## When to re-measure

The marker is a YouTube presentation detail, not a contract. If YouTube restyles
auto-generated descriptions, this silently degrades to "everything looks like a video
upload" — noisy, but never wrong in the dangerous direction. Re-run the join in
`V:\Repos\Yt-dlp_Formats` against `analysis/per-video.csv` to check.
